# NetVplayer 2.0.2

正式构建：**53**，适用于 **macOS 14+／Apple Silicon**。

- 来源实现改为严格选择 **Mac 实现** 或 **Android 原版**。默认使用 Mac；旧“自动／优先”设置迁移至 Mac。两种实现分别加载，不自动切换。
- 修复 Mac 模式加载配置时误准备 Android 环境、长时间停留“正在加载”及 Android 失败遮蔽 Mac 来源的问题。
- Android 环境改为完整签名组件，由发布端组装 JVM、兼容库、宿主及运行依赖。首次使用仅下载完整组件，后续离线复用；用户配置选择的来源 JAR 仍由该配置提供。
- Android 模式不读取 Mac 的网盘凭据或使用 Mac 来源替换；切换实现后需重新启动。

完整 Android 环境的通用桥接／构建源码、固定上游源码及依赖声明见[组件发布附件](https://github.com/spudhero/NetVplayer-Provider-Distribution/releases/tag/android-original-runtime-v1.2.2-arm64)。

直接替换应用即可，无需清除配置、账号、历史或收藏。社区包使用 ad-hoc 签名，安装方式见 [项目说明](https://github.com/spudhero/NetVplayer#安装)。

来源服务、账号授权及上游接口仍可能影响个别来源。既有真实账号、NAS、macOS 14 实机和长期播放的待验范围继续保留；工程回归与代表来源实测不代表全部来源均通过。

## English

Build **53**, for **macOS 14+ / Apple Silicon**.

Select either the Mac implementation or the original Android implementation. Mac is the default, including migration from the former automatic/preferred settings. Each implementation runs independently, with no cross-implementation fallback. Restart after changing the selection.

Fixes Android preparation being triggered in Mac mode, prolonged source loading, and failed Android registrations masking Mac sources. Android now installs a complete signed runtime assembled on the release host. User-selected source JARs remain separate. Android does not reuse Mac cloud credentials or source replacements.

Replace the app without deleting settings. Community ad-hoc signing and existing account, source-service, hardware and sustained-playback validation limits remain applicable.

Generic Android bridge/build sources, fixed upstream sources and notices are supplied with the [complete-runtime release](https://github.com/spudhero/NetVplayer-Provider-Distribution/releases/tag/android-original-runtime-v1.2.2-arm64).

Post-release CI note: the documentation-only follow-up exposed a cold WebKit fixture timeout in `ruleFindsExtensionlessFetch` (1.5 seconds). Its test budget now matches the existing 10-second WebKit checks; the exact extensionless URL assertion remains unchanged. This test-only adjustment does not change the released application bytes.
